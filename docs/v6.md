# v6 — Leibniz notation, a CAS, and demos that teach

## What is actually broken

**The `t–y` curve is in every view.** Views overlap in one frame and everything
supported turns itself on, so `t–y` is always drawn — switch to phase and the
same time curve is still sitting there. The plot is not at fault (the three
views genuinely draw different geometry); the *policy* is. Fix: **a demo
declares the one view it is about**, and loading it turns that view on and the
others off. The user can still turn any view on afterwards — this changes what a
demo arrives as, not what the menu can do.

**`dx/dt` does not parse.** Only `x'` works. Leibniz notation is how most people
write a differential equation, and a tool that refuses it is telling them their
notation is wrong.

## 1. Leibniz notation

```
dx/dt = -y          identical to   x' = -y
d2x/dt2 = -x        identical to   x'' = -x
df/dx = 2x          f' with respect to x
```

The denominator **names the independent variable**. Today that is always `t`;
now the document says what it is, and `t` is merely the default. A document must
be consistent — mixing `dx/dt` and `dy/ds` is an error naming both rows.

This matters beyond convenience: `df/dx = 2x` with `f(0) = 0` integrates to
`f = x²`, so **an integral is a differential equation you already know how to
write**, and the horizontal axis is then labelled `x`, not `t`.

Both spellings are equal citizens: same AST, same everything downstream, and a
document may use either (but one independent variable).

## 2. A CAS worth choosing on the start screen

Numpla should open by asking which of two things you want:

- **Solve & simulate** — everything that exists today.
- **Compute** — a Maple-like pane: type an expression, get it simplified,
  differentiated, expanded.

The second must be real. Minimum honest scope:

- `simplify(e)` — arithmetic folding, identity/zero laws, like terms, canonical
  ordering. It must never change what an expression *means*.
- `diff(e, x)` — symbolic differentiation: sum, product, quotient, chain, powers,
  the builtin functions.
- `expand(e)` — distribute products over sums.
- `subs(e, x, v)` and numeric evaluation.

Not in scope, and say so rather than half-doing it: symbolic integration,
equation solving, limits, series, matrices.

### Contract

```rust
/// Each returns JSON: { ok, input, output, steps?: [...], error? }
/// `output` is Numpla source — it must round-trip through the parser.
pub fn cas_simplify(&self, expr: &str) -> String;
pub fn cas_diff(&self, expr: &str, var: &str) -> String;
pub fn cas_expand(&self, expr: &str) -> String;
pub fn cas_eval(&self, expr: &str) -> String;   // numeric where possible
```

The rule that keeps a CAS trustworthy: **every rewrite preserves value.** A
simplifier that is merely plausible is worse than none, because you cannot tell
when it lied. Test by evaluating input and output at many random points and
comparing.

## 3. Demos, all new

Delete the current gallery and write a fresh one.

- **As few rows as possible.** A demo is read at a glance; rows are the cost.
  Any single row may be as long as it needs to be.
- **Each demo declares `view`**: `'time' | 'phase' | 'polar' | 'field'`. Loading
  it shows exactly that.
- Between them they must demonstrate the notation: `x'`, `x''`, `dx/dt`,
  `df/dx`, an integral written as a differential equation, a function
  definition, a derived row, and a parameter with a slider.
- Cover both **vector fields** and **t–y**, not just one.
- **Several sound demos** — the audio path is a headline feature and needs
  material worth listening to.
- No comments in demo sources. The title and blurb carry the words.
